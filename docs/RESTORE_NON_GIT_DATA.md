# Restoring OpenSpace beyond Git

GitHub contains the durable application and runtime-hub source, tests,
requirements, designs, package manifests, lockfiles, and project documentation.
The retired Mac folders also contained machine-local and regenerable files that
are intentionally excluded from Git.

## Dependencies and generated output

- `openspace-client/node_modules/` and `runtime-hub/node_modules/` account for
  nearly all excluded bulk. Recreate each from its committed lockfile with
  `npm ci` in the corresponding directory.
- `runtime-hub/dist/`, client build output, coverage, Playwright results, and
  temporary logs are generated by the package build and test commands.
- `.opencode/node_modules/` and related logs/artifacts are tool runtime state;
  reinstall the tool dependencies from `.opencode/package.json` when needed.

## Test and service state

Playwright browser state, test results, running service state, and local MCP
process state are not portable project data. Start the services using the
tracked scripts and recreate browser authentication through the normal test
setup. Obtain any required credentials from the authorized service or password
manager; never commit them.

## Earlier secondary workspace

The former non-Git `from-user-dev/openspace` folder contained an earlier set of
PRDs, requirements, agent instructions, and `.sisyphus` planning notes. The
durable documents are recoverable from this repository's earlier Git history;
the complete folder also remains in the independently checksummed external
archive. Its `.opencode` dependency tree and local configuration are
regenerable and are not copied into the current source tree.

## Verification after restoration

Run the client checks from `openspace-client/` and the hub checks from
`runtime-hub/` using the scripts declared in their respective `package.json`
files. The complete pre-cleanup working copies are retained in the verified
`projects.tar` archive created during the Mac cleanup.

At retirement on 2026-09-06, the client typecheck and all 468 client unit tests
passed. The runtime hub built successfully, with 127 of 135 tests passing. The
eight known WIP failures were one voice-API timeout and seven presentation/MCP
contract expectation mismatches in `hub-server.voice-api.test.ts`,
`modality-mcp.presentation.test.ts`, and `modality-mcp.test.ts`. These are the
starting point if development resumes.
